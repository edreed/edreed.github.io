Support for the Storage Performance Development Kit plug-in block devices (BDevs) and modules.

§Supported Block Device (BDev) Modules

The rust-spdk crate currently provides support for the following SPDK-provided block device modules. To use one of these BDevs, add the feature from the Feature column to the rust-spdk dependency in your Cargo.toml file.

ModuleFeatureBuilder
Linux AIO BDevbdev-aioAio::new
Malloc BDevbdev-mallocMallocBuilder
Uring BDevbdev-uringUringBuilder

See Block Device User Guide for more information about the SPDK-provided block device modules in the table above.

§Custom Block Device (BDev) Modules Using rust-spdk

The rust-spdk crate supports writing custom block device (BDev) modules in asynchronous Rust. Add the bdev-module feature to the rust-spdk dependency in your Cargo.toml file to enable this support.

The first step is to define a struct representing the context of your custom BDev. Provide the custom BDev’s implementation using the BDevOps trait. If necessary, you can also provide channel- and/or I/O-specific contexts by defining a struct for each and tying them to your custom BDev through the BDevOps::ChannelContext and [BDevOps::IoContext] associated types, respectively. These associated types can be assigned the unit (()`) type if no additional context is needed by your custom BDev.

Next, define a struct representing the global module context for your custom BDev. Provide the custom BDev’s implementation using the ModuleOps trait, assigning your custom BDev struct to the ModuleOps::BDev associated type. All of the ModuleOps traits methods are provided for you, so you are not required to provide any implementations for it. However, global module initialization and finalization can be performed by providing your own implementations of the ModuleOps::init and ModuleOps::fini methods, respectively. Virtual BDevs may also provide implementations of the ModuleOps::examine_config and ModuleOps::examine_disk methods to examine and claim ownership of, if necessary, other BDev instances as they are registered with the SPDK BDev subsystem.

Finally, decorate your module struct with the spdk::module attribute and start using it from your rust-spdk application. The ModuleOps::new_bdev_builder returns a builder object that you use to create a new instance of your custom BDev.

§Example

The following example implements a simple BDev that ignores writes and returns zeroed blocks on read.

//! # NullRs BVDev Module
//!
//! A custom block device module that ignores write requests and returns zeroed blocks for reads.
use std::io::Write;

use spdk::{
   bdev::{BDev, BDevImpl, BDevOps, IoChannelImpl, IoRequest, IoType, ModuleOps, Owned},
   dma,
   errors::Errno,
   thread,
};

/// Implements the NullRs block device.
///
/// This device ignores write requests and returns zeroed blocks for read requests.
#[derive(Default)]
struct NullRs;

unsafe impl Send for NullRs {}
unsafe impl Sync for NullRs {}

impl NullRs {
   const BLOCK_SIZE: u32 = 4096;
   const NUM_BLOCKS: u64 = 65536;

   /// Creates a new NullRs block device.
   pub async fn new_device() -> spdk::Result<BDev<Owned>> {
       NullRsModule::new_bdev_builder(c"null-rs", Self::BLOCK_SIZE, Self::NUM_BLOCKS)
           .build()
           .await
   }
}

impl BDevOps for NullRs {
   type ChannelContext = ();
   type IoContext = ();
   type IoError = Errno;

   async fn destruct(&mut self) -> spdk::Result<()> {
       Ok(())
   }

   fn io_type_supported(&self, io_type: IoType) -> bool {
       matches!(io_type, IoType::Read | IoType::Write)
   }

   fn new_io_channel(&mut self) -> spdk::Result<()> {
       Ok(())
   }

   async fn handle_io(
       _this: &BDevImpl<Self>,
       _channel: &IoChannelImpl<()>,
       io: &mut IoRequest<()>,
   ) -> spdk::Result<()> {
       if io.io_type() == IoType::Read {
           let dst = io.buffers_mut();

           dst[0].fill(0);
       }

       Ok(())
   }
}

/// Implements the NullRs block device module.
#[spdk::module(product_name = "Null Disk")]
#[derive(Debug, Default)]
struct NullRsModule;

impl ModuleOps for NullRsModule {
   type BDev = NullRs;
}

/// A program that creates and writes to the NullRs block device.
#[spdk::main]
async fn main() {
   let null = NullRs::new_device().await.unwrap();

   thread::spawn_local(async {
       // Open the NullRs block device in a separate asynchronous task to scope the lifetime of
       // the descriptor and I/O channel. These must be dropped before the NullRs block device can
       // be destroyed.
       let desc = null.open(true).unwrap();
       let ch = desc.io_channel().unwrap();
       let layout = null.layout_for_blocks(1).unwrap();
       let mut buf = dma::Buffer::new_zeroed(layout).unwrap();

       write!(buf.cursor_mut(), "Hello, World!").unwrap();

       ch.write_at(&desc, &buf, 0).await.unwrap();
   })
   .await;

   null.destroy().await.unwrap();
}

The Echo BDev Module and PassthruRs Virtual BDev Module examples demonstrate more complex BDev implementations.

See Writing a Custom Block Device Module for general information about writing a custom plug-in block device modules for the SPDK.
